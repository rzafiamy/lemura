# Advanced Execution

## What this is
Advanced Execution techniques govern how the ReAct agent executes, recovers, and concludes. They are runtime guards distinct from Context Compression. Currently lemura supports five runtime capabilities that are configured directly within `SessionConfig`.

## How it works

- **ToolResponseProcessor**: Determines whether a massive file generated by a tool should be blindly fed back into context, risking an overflow, or compressed extraction-style before the model reads it.
- **ContinuationPlanner**: Orchestrates multi-step dependent execution sequences between different tools.
- **GoalInjector**: Guarantees the top-level goal maintains visibility independently of context truncation bounds.
- **FinalResponseFormatter** & **StepCounter**: Together bounds the `maxSteps` count to force the model into a standard JSON or MarkDown wrap-up summarization format before cutting it off entirely.

## Configuration

These advanced mechanisms map to `SessionConfig` properties seamlessly:
- `toolResponseProcessor: IToolResponseProcessor`
- `maxSteps: number`
- `enableContinuationPlanning: boolean`
- `enableGoalPlanning: boolean`

## Examples

```ts
import { SessionManager, ToolResponseProcessor } from 'lemura';

const manager = new SessionManager({
  adapter,
  model: 'gpt-4o',
  maxTokens: 50000,
  maxSteps: 15,
  toolResponseProcessor: new ToolResponseProcessor()
});
```

## When things go wrong
- **Agent loops infinitely:** Check `StepCounter` configurations. Make sure `maxSteps` isn't exceptionally large. 
- **Tool responses are truncated uselessly:** Review the `ToolResponseProcessor.evaluate()` behavior. It may be overly aggressively matching the `sizeClass`.
