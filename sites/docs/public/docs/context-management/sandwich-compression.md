# Sandwich Compression Strategy

`SandwichCompressionStrategy` is lemura's most commonly used compression strategy. It preserves the beginning and end of a conversation — the "bread" of the sandwich — while summarizing everything in the middle.

---

## The Core Idea

Long conversations have a natural structure:
- **Head** (turns 1–N): System context, initial instructions, first user message
- **Middle** (the bulge): Back-and-forth reasoning, tool calls, iterative refinement
- **Tail** (last M turns): Current task context, very recent exchanges

The head contains the "why" of the session. The tail contains "where we are now." The middle is mostly intermediate reasoning that can be summarized without losing critical context.

## Configuration

```typescript
import { SandwichCompressionStrategy } from 'lemura/context';

const strategy = new SandwichCompressionStrategy(adapter, {
  preserveFirst: 2,        // Keep the first N turns verbatim (anchors)
  preserveLast: 4,         // Keep the last M turns verbatim (recency)
  triggerThreshold: 0.80,  // Run when context reaches 80% of maxTokens
  summaryMaxTokens?: 500,  // Max size of the generated summary (optional)
  priority?: 2,            // Order in strategy stack (lower = first)
});
```

### Summary injection

The compressed middle is replaced by a synthetic `system` turn:
```
[CONVERSATION SUMMARY]
The user asked about optimizing a database schema. We analyzed the current 
schema (3 tables, 12 columns), identified N+1 query patterns in the orders 
endpoint, and discussed adding a composite index on (user_id, created_at). 
The user confirmed the index approach and asked to see the migration SQL.
[/CONVERSATION SUMMARY]
```

## When to Use SandwichCompressionStrategy

| Use case | Why sandwich? |
|---|---|
| **Customer support chatbot** | Preserve initial greeting + rules, recent customer context |
| **Code review assistant** | Preserve original code file, recent diff discussion |
| **Multi-turn interview** | Preserve first questions asked, recent answers |
| **General-purpose agents** | Good default — handles most conversation shapes |

## Tuning `preserveFirst` and `preserveLast`

```typescript
// Short chats — preserve more
new SandwichCompressionStrategy(adapter, {
  preserveFirst: 3,   // instruction + initial message + first reply
  preserveLast: 6,    // recent 3 exchanges
  triggerThreshold: 0.75,
})

// Long research sessions — preserve less head, more tail
new SandwichCompressionStrategy(adapter, {
  preserveFirst: 1,   // only initial system context
  preserveLast: 8,    // recent 4 exchanges (many tool calls per turn)
  triggerThreshold: 0.80,
})

// Code-heavy sessions with large tool outputs
new SandwichCompressionStrategy(adapter, {
  preserveFirst: 1,
  preserveLast: 2,
  triggerThreshold: 0.65,  // compress earlier — tool outputs are big
})
```

> **Rule of thumb:** `preserveFirst + preserveLast` should be ≤ 40% of your expected turn count. If a conversation typically runs 20 turns, preserve at most 8.

---

## The Summary Is Persistent

The summary generated by this strategy accumulates in `context.compressionSummary`. Each time the strategy runs again, it summarizes the *new* middle content and appends to the existing summary. This means:

- First compression: 5,000 tokens → 300-token summary ✅
- Second compression: New middle grows → appended summary ✅
- The accumulated summary is always injected before the current conversation via `SummaryInjectionStrategy`

```typescript
// Always pair SandwichCompressionStrategy with SummaryInjectionStrategy:
compressionStrategies: [
  new SummaryInjectionStrategy({ priority: 1 }),  // inject summary before every call
  new SandwichCompressionStrategy(adapter, { priority: 2, ... }),
]
```

## Under the Hood

When `apply()` is called:

```typescript
async apply(context: ContextWindow): Promise<ContextWindow> {
  const head = context.turns.slice(0, this.config.preserveFirst);
  const tail = context.turns.slice(-this.config.preserveLast);
  const middle = context.turns.slice(this.config.preserveFirst, -this.config.preserveLast);

  // Call the provider to summarize the middle
  const summary = await this.adapter.complete({
    model: this.config.summaryModel ?? context.model,
    messages: [{
      role: 'user',
      content: `Summarize this conversation segment in a concise paragraph, preserving key decisions and facts:\n\n${formatTurns(middle)}`,
    }],
    maxTokens: this.config.summaryMaxTokens ?? 500,
  });

  const summaryTurn: Turn = {
    role: 'system',
    content: `[CONVERSATION SUMMARY]\n${summary.content}\n[/CONVERSATION SUMMARY]`,
    tokenCount: this.adapter.estimateTokens(summary.content),
    compressed: true,
  };

  return {
    ...context,  // ← immutable — spread and return NEW object
    turns: [...head, summaryTurn, ...tail],
    compressionSummary: (context.compressionSummary ?? '') + '\n' + summary.content,
    tokenCount: this.recount([...head, summaryTurn, ...tail], context),
  };
}
```

## Tips & Tricks

> **Tip:** Use a different (cheaper, faster) model for summarization to save costs. Pass `summaryModel: 'gpt-4o-mini'` in the config to use a fast model for compression while your main agent uses `gpt-4o`.

> **Tip:** If the summary quality is poor (model forgets important details), increase `summaryMaxTokens`. The default 500 tokens is conservative — for information-dense conversations, 800–1000 tokens produces much better summaries.

> **Tip:** Monitor compression events to understand when and how often compression fires:
> ```typescript
> session.on('strategy:applied', ({ strategyName, tokensBefore, tokensAfter }) => {
>   if (strategyName === 'sandwich') {
>     console.log(`Sandwich saved ${tokensBefore - tokensAfter} tokens`);
>   }
> });
> ```
